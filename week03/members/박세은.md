# 박세은

- GitHub ID: seeunparkdev
- git-practice의 `git log --oneline` 결과 (3개 이상):
  ```
  ea5eeb6 Add: 배운 명령어 목록 추가
  cc434ea Add: hello.md에 실습 기록 추가
  975db18 Add: hello.md 추가
  ```
- working directory / staging area / repository를 내 말로 설명하기: working directory는 내가 실제로 파일을 만들고 수정하는 작업 공간이고, staging area는 다음 커밋에 넣을 변경 사항만 골라 담아 두는 대기 공간이며, repository는 커밋한 기록이 `.git` 폴더 안에 저장되는 곳입니다.
- `add` 와 `commit` 을 나눠 놓은 이유 (실습 3 경험으로): 실습 3에서 `commands.md`와 `memo.md`를 함께 만들었지만, 완성된 `commands.md`만 `add`해서 커밋하고 아직 정리 중인 `memo.md`는 커밋에서 뺄 수 있었습니다. 여러 파일을 수정해도 원하는 것만 골라 하나의 커밋으로 묶을 수 있도록 두 단계로 나뉘어 있습니다.
- `git diff` 와 `git diff --staged` 의 차이: `git diff`는 수정했지만 아직 `add`하지 않은 변경 내용을 보여 주고, `git diff --staged`는 `add`는 했지만 아직 커밋하지 않은 변경 내용을 보여 줍니다.
- `git restore` 를 써 본 상황: `hello.md`에 "실수로 쓴 내용!!!"을 추가한 뒤 `git restore hello.md`로 마지막 커밋 상태로 되돌렸고, `commands.md`를 `add`했다가 `git restore --staged commands.md`로 add만 취소해 봤습니다.
- 이번 주 소감: 파일이 working directory, staging area, repository를 차례로 이동하는 과정을 직접 확인하니 add와 commit의 차이를 알 게 되었습니다.
